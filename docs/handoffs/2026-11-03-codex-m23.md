## What failed and what changed

Original CI run: https://github.com/Aulteran/FileCanopy/actions/runs/41569843848.
Six jobs passed; `e2e` and `compose (app)` each had two failures.

1. **Dialog keyboard focus:** native `<dialog>` made the background inert but Tab could leave the
   dialog for browser chrome. `apps/web/src/Dialogs.tsx` now cycles Tab/Shift+Tab at the first/last
   enabled, visible control. Escape, native modality and opener restoration remain in place. The
   existing accessibility e2e tests containment in both directions, Escape and focus return.
2. **First-run test order:** `test_accessibility.py` sorts before `test_browser_ui.py` and initializes
   the shared instance through `world`. The bootstrap browser test now uses a dedicated
   `fresh_stack` fixture with teardown, independent of session-stack initialization.
3. **Rename race:** the new test omitted required `expected_revision`, so it tested 422 validation
   failures. All six contenders now use the captured revision and must produce exactly one 200
   and five 409 responses for each of eight files. Listings must all succeed. Thread-pool futures
   propagate request exceptions to the main test; filesystem/DB consistency checks remain.
4. **Log canary:** `Client.call()` parses JSON, but the OIDC callback redirects to the HTML SPA.
   The test now uses `raw()`, verifies the HTML response and failed-login status, and requires both
   `/search` and `/auth/oidc/callback` in the logs before checking for leaked canaries.

Also diagnosed the earlier **Windows setup-token problem**: the test runner was reading the real
`deploy/.env`, whose fixed setup token suppresses generated-token logging. `Stack` now passes an
empty temporary `--env-file` and removes inherited `FILECANOPY_*` / `COMPOSE_*` configuration.
Tests deliberately set any overrides they need afterwards. Backup tests now reuse this runner
through `self.files` rather than duplicating the Compose command. The operator's `.env` is untouched.

`.prettierignore` and `.dockerignore` exclude `.claude/worktrees` so local Claude worktrees do not
fail formatting or enter Docker build contexts. No files in those worktrees were changed.

Follow-up failure-path review reproduced a real leak missed by the original canary: nginx HTTP
error diagnostics logged OIDC code/state when the API was unavailable. The http-level error log
is now discarded (`error_log /dev/null`), because it cannot use the access-log redaction format.
Path-only access logs still record 502 responses; API exception-type and global nginx lifecycle
logs remain. The operator guide documents the tradeoff. Uvicorn also retained its own default stderr
traceback formatter after app startup; it now propagates through the JSON exception-type
formatter. A new test reproduces the actual Uvicorn-first startup sequence and checks stderr. The Compose canary now exercises both
successful requests and API-down failure/recovery, and checks that neither stream leaks secrets.

## Independent security review follow-up

Review of `9535141`: https://github.com/Aulteran/FileCanopy/pull/31#issuecomment-6598009037. The user asked Codex to work through the findings.

- **High: token mint vs forced sign-out.** `auth.service.lock_account` is shared by MCP creation
  and account-wide revocation. PostgreSQL uses `FOR NO KEY UPDATE`, which serializes credential
  changes while allowing audit/session foreign-key checks. Creation refreshes account and session
  under that lock, checks active/revoked/expiry/idle/locked state, and checks proof against the fresh
  state. The lock is held through insertion. Session locks follow account locks.
- **Medium: proposal history retained model text.** Label raises now bulk-scrub names, suggested
  folders, reasons and document types across every proposal status under the current subtree,
  preserving status/history and unrelated proposals. Proposal storage and label changes take the
  existing tree advisory lock; storage refreshes the node and rechecks privacy/snapshot. Retiring
  a replaced proposal no longer commits in the middle of that final transaction.
- **Medium: hostile-name tests bypassed operations.** Copy now uses `target_parent_id`; rename
  supplies the current revision. Each operation has its own destination to avoid accidental
  collision-only coverage. The test requires its expected success code or `INVALID_NAME`; only
  the intentionally overlong name may produce schema-level `VALIDATION_ERROR`.
- Added disabled-account coverage using an already authenticated browser and MCP token; denied
  node response bodies are checked for names, content words and ids, collection membership/count
  is exact, and unauthorized filename/body searches must contain neither hits nor positive counts.
